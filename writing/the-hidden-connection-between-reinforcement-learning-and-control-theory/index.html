The Hidden Connection Between Reinforcement Learning and Control Theory

A policy is a controller. Following that connection reveals how learning, planning, and stability fit into the same decision problem.

2026-11-15

An action changes the world. It also changes which actions will be useful next.

Let’s switch gears for a moment and talk about reinforcement learning. The previous three essays asked how an AI system might improve its own research process. Here I want to step back to a more basic question: how does a system learn to act when its actions change what happens next?

The controller examples in those essays offer a useful place to start. A controller observes a system, chooses an action, and receives feedback. An RL agent does the same. One might adjust a motor, and another might choose a move in a game. Both must live with the future their actions create.

I find this connection interesting because reinforcement learning and control theory often arrive dressed very differently. One comes with agents, rewards, and learning curves. The other comes with dynamics, feedback, and stability. Following the mathematics makes that separation much harder to maintain.

I think the most useful connection is that learning a good policy and designing a good controller are parts of the same problem. We need to account for future consequences, learn what we do not know, and establish which behaviors we can trust.

That does not make the fields interchangeable. It gives us a way to carry questions from one into the other.

A policy is a controller

Start with a deterministic system:

xt+1=f(xt,ut).x_{t+1}=f(x_t,u_t).

The state xtx_t describes the system now. The action utu_t influences what happens next. A feedback controller chooses ut=μ(xt)u_t=\mu(x_t).

In RL notation, we might write the state as sts_t, the action as ata_t, and the policy as π\pi. A deterministic policy chooses at=π(st)a_t=\pi(s_t). A stochastic policy instead specifies a distribution π(a∣s)\pi(a\mid s). Either way, it supplies the rule for acting on what the agent knows.

For the moment, assume the state contains the information needed to predict the next-state distribution given an action. This is the Markov assumption. When we observe only part of the system, a single observation may not suffice: a controller or policy may need memory, a state estimate, or a belief about hidden variables.

The objective also translates. For a fixed policy and initial state, define discounted expected cost:

Jπ(x)=Eπ ⁣[∑t=0∞γtc(xt,ut) | x0=x],0≤γ<1.J^\pi(x)=\mathbb E_\pi\!\left[ \sum_{t=0}^{\infty}\gamma^t c(x_t,u_t)\,\middle|\,x_0=x \right],\qquad 0\leq\gamma<1.

If reward is negative cost, r=−cr=-c, then the corresponding reward value is Vπ=−JπV^\pi=-J^\pi, whenever the expectations are well-defined. Maximizing one is minimizing the other. Stochastic transitions change the expectation, not this equivalence.

So the shared structure is already present before we choose a learning algorithm. RL asks how experience can help us find a good decision rule. Optimal control asks how to choose actions to optimize behavior over time. These questions meet naturally in dynamic programming. Szepesvári, Algorithms of Reinforcement Learning.

The future enters through a value function

For a discounted Markov decision process with bounded rewards, the optimal reward value satisfies the Bellman equation, assuming the maximum is attained:

V∗(s)=max⁡a{r(s,a)+γ E ⁣[V∗(s′)∣s,a]}.V^*(s)=\max_a\left\{ r(s,a)+\gamma\,\mathbb E\!\left[V^*(s')\mid s,a\right] \right\}.

Here r(s,a)r(s,a) is expected immediate reward, and s′s' is the next state. The second term is what makes the problem sequential. An action can be attractive now and leave us somewhere expensive later.

I like thinking of a value function as a summary of future consequences. It does not reconstruct every possible trajectory. It compresses those trajectories into an expected return for a particular objective and continuation policy. Change the objective or policy, and that summary generally changes too.

The Bellman equation tells us how immediate consequences and future value fit together. It does not, by itself, tell us how to compute the value function in a large unknown environment. That is where models, approximation, and data enter.

Before adding those difficulties, though, it is worth seeing a case we can solve.

A controller we can work out by hand

The linear quadratic regulator, or LQR, combines linear dynamics with a quadratic cost:

xt+1=Axt+But,c(xt,ut)=xt⊤Qxt+ut⊤Rut.x_{t+1}=Ax_t+Bu_t,\qquad c(x_t,u_t)=x_t^\top Qx_t+u_t^\top Ru_t.

Consider the undiscounted infinite-horizon problem, with full state observation and no action constraints. To keep the assumptions simple, take QQ and RR positive definite and assume (A,B)(A,B) is stabilizable: some linear feedback can make the dynamics decay toward zero. The optimal cost-to-go is quadratic, J∗(x)=x⊤PxJ^*(x)=x^\top Px, and the optimal controller is linear, u=−Kxu=-Kx. The Riccati equation determines PP and hence KK. Tedrake, Linear Quadratic Regulators.

We can see the mechanism without a matrix calculation. Suppose:

xt+1=xt+ut,c(xt,ut)=xt2+ut2.x_{t+1}=x_t+u_t,\qquad c(x_t,u_t)=x_t^2+u_t^2.

The state might represent a deviation from a desired level. Moving it costs effort; leaving it away from zero costs something too. This is an illustrative mathematical system, not a measured physical process.

If we minimize only the current cost, we choose ut=0u_t=0: the current xt2x_t^2 is already fixed, and any action adds effort. But doing nothing leaves the same deviation tomorrow.

Try a quadratic cost-to-go, J∗(x)=px2J^*(x)=p x^2. Bellman’s equation in cost form becomes:

px2=min⁡u{x2+u2+p(x+u)2}.p x^2=\min_u\left\{x^2+u^2+p(x+u)^2\right\}.

Differentiating the right-hand side with respect to uu gives:

u∗=−p1+px.u^*=-\frac{p}{1+p}x.

Substitution gives p2−p−1=0p^2-p-1=0. Taking the positive solution:

p=1+52,u∗=−5−12x≈−0.618x.p=\frac{1+\sqrt{5}}{2},\qquad u^*=-\frac{\sqrt{5}-1}{2}x\approx-0.618x.

The resulting next state is approximately 0.382x0.382x. The controller pays some effort now because reducing the deviation saves future cost. That tradeoff is exactly what the value function represents.

This is the bridge I want to keep in view. An RL method applied to this problem could try to learn the policy or its value from experience. The analytic solution gives us something precise to compare it with. If we use reward r=−cr=-c, the optimal reward value is −px2-p x^2, not px2p x^2. The sign changes with the convention, but the preferred action does not.

What do we know, and what must we learn?

It is tempting to summarize the difference as “control knows the model, and RL learns without one.” That leaves out too much. Control includes system identification and adaptive methods. RL includes methods that learn a model and plan with it. Nonlinearity and uncertainty belong to both fields.

A more useful distinction is what we choose to represent explicitly. We might estimate dynamics, learn a value function, learn a policy directly, or combine all three. Each choice places the approximation error somewhere different.

Model predictive control, or MPC, makes one such choice visible. At the current state xtx_t, a nominal finite-horizon planner solves a problem of the form:

min⁡u^0,…,u^H−1∑k=0H−1c(x^k,u^k)+Jf(x^H)subject tox^0=xt,x^k+1=f^(x^k,u^k),(x^k,u^k)∈C,x^H∈Xf.\begin{aligned} \min_{\hat u_0,\ldots,\hat u_{H-1}}\quad& \sum_{k=0}^{H-1}c(\hat x_k,\hat u_k)+J_f(\hat x_H)\\ \text{subject to}\quad&\hat x_0=x_t,\\ &\hat x_{k+1}=\hat f(\hat x_k,\hat u_k),\\ &(\hat x_k,\hat u_k)\in\mathcal C,\quad \hat x_H\in\mathcal X_f. \end{aligned}

The hats mark predictions. C\mathcal C describes allowed states and actions; JfJ_f and Xf\mathcal X_f are a terminal cost and terminal set. Their design matters for what the controller can guarantee. The controller applies only the first action, observes the new state, and replans. This is feedback even though each optimization produces a whole sequence. Rawlings, Mayne, and Diehl, Model Predictive Control.

For the scalar example, planning one step with no terminal cost gives the shortsighted action u=0u=0. Add the exact terminal cost Jf(x)=px2J_f(x)=p x^2, and that same one-step optimization recovers the infinite-horizon solution above. The future has entered through one number, pp.

This suggests a natural collaboration: use a model for the near future and a learned cost-to-go for what lies beyond it. In reward notation, the corresponding cost is the negative of the reward value. Learning that terminal approximation does not automatically preserve the guarantees of a particular MPC design. It gives us a new component whose errors need to be understood.

A good score is not a stability argument

The LQR example does more than produce a low cost. Its state converges to zero. Can we expect that from any policy with a favorable return?

A small counter-example shows why the distinction matters. Consider the fixed dynamics xt+1=2xtx_{t+1}=2x_t, with cost xt2x_t^2 and discount γ=1/8\gamma=1/8. Then:

∑t=0∞(18)txt2=x02∑t=0∞(12)t=2x02.\sum_{t=0}^{\infty}\left(\frac18\right)^t x_t^2 =x_0^2\sum_{t=0}^{\infty}\left(\frac12\right)^t =2x_0^2.

The discounted cost is finite even though the state diverges whenever x0≠0x_0\neq0. This is not a claim that such a policy is optimal. It shows that a finite discounted objective alone does not establish stability. Discounting can make a distant failure look small.

For our scalar LQR controller, we can establish convergence directly. Write u=−kxu=-kx and take W(x)=x2W(x)=x^2. Then:

W(xt+1)−W(xt)=[(1−k)2−1]xt2.W(x_{t+1})-W(x_t) =\left[(1-k)^2-1\right]x_t^2.

For 0<k<20<k<2, the difference is negative away from zero, and xt=(1−k)tx0x_t=(1-k)^t x_0 converges to zero. Our optimal gain lies in that interval. This is a simple Lyapunov argument: a positive measure of deviation decreases along the actual closed-loop dynamics. General versions require conditions on the dynamics, function, and region where the inequalities hold. Åström and Murray, Feedback Systems, Chapter 5.

Add a delay, an action limit, or persistent noise, and we have changed those dynamics. The same calculation no longer settles the question. A learned controller deserves the same scrutiny.

Robust optimization asks a related question about uncertainty. If θ\theta indexes plausible dynamics, one formulation is:

min⁡πmax⁡θ∈ΘJ(π,θ).\min_\pi\max_{\theta\in\Theta}J(\pi,\theta).

This asks for performance against the worst model in the declared set. It offers no protection against everything outside that set. I would want to see how Θ\Theta was chosen, what failures it represents, and what useful behavior the resulting conservatism costs.

An action can teach us something

There is another consequence of uncertainty: an action can change both the system and our knowledge of it.

Imagine an actuator whose response is weaker than expected. Is its gain low, or does it respond after a delay? Increasing the input may reduce the immediate error, but a carefully timed change might distinguish the explanations. That information could improve later decisions. Whether the probe is worthwhile depends on its immediate cost, the remaining horizon, and how much the answer would change the policy.

RL makes this exploration–exploitation tradeoff central. Control theory also studies it through dual control, where actions both influence and help identify the system. Klenske and Hennig develop this connection explicitly in approximate Bayesian RL. Their work is a useful reminder that learning and control have been intertwined for a long time. Klenske and Hennig, 2016.

The question is therefore broader than whether to use a model. We must also decide how to collect the information that will make the next model or policy more useful.

The same structure appears in resource allocation

To move beyond a physical controller, consider a hypothetical advertising campaign with budget BB over TT periods. At each period, an action controls participation in available opportunities. Let dtd_t be realized spend and btb_t remaining budget:

b0=B,bt+1=bt−dt,0≤dt≤bt.b_0=B,\qquad b_{t+1}=b_t-d_t,\qquad 0\leq d_t\leq b_t.

The last condition must be enforced by the spending mechanism if the budget is a hard constraint. A penalty in an expected reward does not itself enforce it. The objective might be to maximize expected total value, Eπ[∑t=0T−1rt]\mathbb E_\pi[\sum_{t=0}^{T-1}r_t].

This is a sequential decision problem even when each reward arrives immediately. Spending now removes options later. A useful state must include remaining budget and time, together with whatever information is needed about future opportunities.

We can also approach it through feedback. Choose a desired remaining-budget trajectory bˉt\bar b_t and measure:

et=bt−bˉt.e_t=b_t-\bar b_t.

A positive error means we have spent less than the schedule intended. A pacing controller could respond by participating more aggressively.

But tracking a schedule and maximizing value are different objectives. If tomorrow’s opportunities are much better, saving budget may be the right decision even while it creates a pacing error. That is where the value function becomes useful: it represents the future opportunity cost of spending now.

I would use this tension to choose a comparison. Does a learned policy earn more value because it predicts future opportunities, or does it simply repair a poorly tuned pacing rule? Does it still respect the same budget? Those questions are more informative than deciding in advance whether the problem belongs to RL or control.

Start with a controller you can understand

A PID controller is a useful example of a transparent feedback rule. For sampled error ete_t and sampling interval Δt\Delta t, an idealized discrete form is:

ut=KPet+KIΔt∑j=0tej+KDet−et−1Δt.u_t=K_Pe_t+K_I\Delta t\sum_{j=0}^{t}e_j +K_D\frac{e_t-e_{t-1}}{\Delta t}.

The proportional term reacts to the error now. The integral term remembers persistent error: a small mismatch that never goes away keeps accumulating. The derivative term reacts to how quickly the error changes, which can help moderate an approaching overshoot.

Those simple descriptions also expose practical problems. Differencing noisy measurements can produce noisy actions. If an actuator reaches its limit while the integral keeps accumulating, the controller can continue demanding more than the system can deliver. Filtering and anti-windup address these issues, but their design and tuning matter. Åström and Murray, PID Control.

I would not assume PID is the right controller for every allocation or learning problem. I would ask what a carefully tuned simple controller can already do. That gives a learned policy a meaningful burden of proof.

Rich observations, nonlinear interactions, and heterogeneous future opportunities may justify a more flexible policy. A neural network can represent decision rules that are difficult to write down. Flexibility also expands what must be learned and tested. The interesting comparison is the value of that flexibility under the same information, constraints, and evaluation conditions.

When the controller itself learns

Actor–critic methods make the distinction between acting and improving the actor explicit. The actor, πθ(a∣s)\pi_\theta(a\mid s), chooses actions. A critic estimates value, and learning uses that estimate to update the actor. There is a loop through the environment and another through the policy parameters. Szepesvári, Algorithms of Reinforcement Learning, Section 4.4.

I find it useful to view these as interacting processes, rather than assume the learning loop will automatically improve the behavior loop. The actor changes which experiences arrive. Those experiences change the critic. The critic then influences the next actor update. Errors can feed back through that interaction too.

We can extend the view to a training process: an outer decision rule might choose a learning rate, allocate compute, or select data. That is a way to formulate a new sequential decision problem, provided we specify its state, actions, observations, and objective. It is not yet an effective algorithm.

It is also not, by itself, recursive self-improvement. A fixed update rule can keep improving a controller without improving the procedure that produces those updates. That is the distinction from the earlier essays worth carrying forward.

What I want to bring from one field to the other

The controller in this essay started with a single state and an exact solution. As we added unknown dynamics, limited observations, constraints, and learning, the problem became harder. The underlying question stayed recognizable: what action is useful now, given the future it creates?

Control theory encourages me to ask what feedback does to the dynamics, which assumptions support stability, and where uncertainty enters. RL encourages me to ask what can be learned from experience, what information an action provides, and how to represent consequences that are hard to calculate explicitly.

Neither perspective removes the need to test the resulting system. Feedback can correct a mistake, but delayed or misleading feedback can also amplify one. A better return can be meaningful without answering every question about behavior.

That brings me back to the evaluator essay from a different direction. We need to know what our objective rewards. We also need to understand the dynamics produced by pursuing it. A policy is a controller, and the system it creates is ultimately what we have to evaluate.
